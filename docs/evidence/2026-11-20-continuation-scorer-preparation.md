# Preparing the eight real continuations for review

Both prompts and the human review questions are frozen for all eight tasks.
On matched Windows source trees, the historical fix passed and the interrupted
version failed a behavior check or lacked a required implementation in every
case. Seven pairs also passed the control check inside the isolated Windows
scorer. The settlement game passed all three ordinary Windows browser tests,
but its browser cannot reach the local game host inside either isolated scorer.
Benchmark admissions, Claude calls, human judgments on
real cases and experimental spend are all zero for this batch.

## What a reviewer will see

For each result, the reviewer gets the same question and expected value beside
the observed row, message or output. For example, the recovery card asks
“After the restart and retry, is there exactly one entry for r1 in the log?”
The expected value is one. A missing log leaves that question at **Cannot judge**.
The reviewer can then choose which recovery record they would use and cite the
entry that informed their choice. The [eight case definitions](../../experiments/continuation-review/heldout-cases.json)
contain the exact wording. Actual result cells and preferences await worker artifacts.

## What was frozen

The [preparation tool](../../experiments/continuation-review/prepare_cohort.py)
checks each source file and each retained history against the original intake
hashes. The case briefs are retrospective summaries of identified events from
before the interruption. The event hashes keep each summary traceable to the
private source. Both approaches receive the same starting files, edit permissions
and full brief. The reviewer questions and later reference implementations stay
with the operator.

The plain prompt renders the retained facts as text. The TORC prompt uses the
existing P5 compiler, its 400-word carry setting from the development study,
and the verified claim capsule. The compiler and its settings stayed fixed
across the cohort. All eight capsules retained every selected section. Two
fresh preparations reproduced all sixteen prompt files, eight review packets
and the top-level receipt byte for byte. These hashes measure file integrity.
Provider input tokens will come from the execution owner's ledger.

The WoW helper briefing needed one correction to the recovered edit permissions.
The original proposal included handling zero money and experience at logout,
and the user authorized the offline work. Six additional file paths cover the
main add-on, the two reader modules, documentation and attribution. Both
approaches receive exactly those same permissions. The historical intake
remains available. Retail and launch-day behavior still require observations
from an actual game client.

## How the controls were checked

For each task, the interrupted control uses the retained source bytes. The
reference control starts on that same tree and receives only permitted files
from the recorded reference commit. The tests and dependency inputs are fixed
across each pair. Opaque IDs and file hashes bind each candidate before the
score is read. The historical controls establish whether a check can distinguish
the two source states. They do not contribute observations to the comparison.

| Task | What the checks inspect |
|---|---|
| PowerShell arguments | A property name with a space stays in one argument and a trailing empty argument survives. |
| Coordinator | Removing a selected player clears the selection. Roster revisions and writer pauses follow the session rules. |
| Journal and restart | A retried move keeps its original revision and appears in the log once. |
| Workflow forecasts | Reimporting a patch preserves the four forecast IDs and their checkpoint. |
| Incremental collection | Claude and Codex return the new event IDs and final task state without preparing discarded earlier events. |
| Agy routing | A recording executor sees a direct Agy launch and a completion checker for Claude launches. |
| Settlement pages | Two player pages and a public board show the move, refusal, and same-seat reconnect against a real local game host. |
| WoW helper | Recorded clipboard and image inputs, packet freshness, the opt-in probe and a synthetic logout save. |

The coordinator used the lockfile recovered at the interruption. The other
Tableforge checks received matched dependency inputs. The settlement checks
applied the same recorded line-ending correction to 49 game assets. Autowork's
Claude control received the completion policy at the parent repository's
recorded submodule commit. Tuan used the schema shipped in its task tree.
The final WoW job uses offline inputs and omits the two platform clipboard probes.
Setup and sandbox errors are recorded separately from failures in a candidate.

## What still prevents the comparison

All sixteen Windows candidate packages reached the earlier macOS scorer with
matching file bytes and manifest hashes. Its executable, execution-owner
sources and runtime matched the earlier qualification. On both Windows and
macOS the isolated process could read its own control file and was denied
the external control file and host listener. Both also denied a loopback
connection created entirely inside the scoring job.

The settlement test needs that last connection to exercise a browser reload
against the live local game host. The next engineering step is a scorer in
which that browser and host can communicate privately while external network
and private-file access remain denied. Repeat the positive and negative
controls there. The scorer gate remains open until the actual browser job
can score both candidate states. Per-call Claude accounting follows under
its existing, separate prerequisite.
