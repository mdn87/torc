# Authorized diagnostic execution

Matt authorized execution of the takeover stages on October 21, 2026, with a
$2 ceiling, subscription CLI preference, acceptance of limited measurements,
and baseline changes when a cold condition is infeasible. These decisions
resolve the three operator questions in the October 20 takeover plan.

## Measurement and baseline amendment

The primary pilot output is per-workload acceptance and reported usage, with
missing counters and unknown provider-internal retries retained. Whole-task
savings, actual API cost, provider-cache savings and adoption remain unavailable.
The original full-coverage endpoint, 20% target and five-point quality margin
remain unchanged in the offline analysis contract; this diagnostic does not
claim to satisfy them. Two historical workloads do not support population claims.

Drop the intended `native_cold` arm. The retained fresh-session control reported
7,296 cached input tokens, and the qualified owner has no cache-purge capability.
Keep `compiled_prompt`, `torc_capsule` and `native_warm`. Here `native_warm`
means a fork of a real seeded native session, not an asserted warm provider
cache. Both portable arms start new native sessions. All arms keep the same
public task, history, source and tool access. Report observed cache counters
separately; do not rename unknown cache state as cold.

## Frozen resource limits

- Two historical workloads, three arms, one repetition: six comparative workers.
- One native seed per workload: two preparation workers, charged separately and
  included in the whole pilot boundary. Eight planned CLI invocations total.
- Nine total admissions is the ceiling, including failed starts. The ninth slot
  does not authorize an automatic retry or replacement. At most 600 seconds per
  worker; at most 5,400 admitted worker-seconds; no automatic retries or fallback.
- This separately authorized comparative cohort does not consume or reset the
  original qualification root, whose balance remains six of nine used.
- Paid API use is disabled. The operator's $2 ceiling remains a ceiling, not a
  spending target. Subscription usage is recorded without inventing a dollar cost.
- A missing termination receipt, unresolved admission, broken isolation control,
  changed source pin or ambiguous native binding stops further admissions.
  An ordinary task failure is retained and does not replace the scheduled task.

## Ownership and launch

TORC produces immutable contexts, candidate bindings, scoring packets and
descriptive reports. Its existing draft manifests still say
`launch_authorized: false`. They never grant execution authority.

Autowork owns assignment, route selection, native state, isolated worktrees,
process capture, usage and termination. The existing read-only native canary
entry point must not be relabeled as a writable comparison entry point. A
comparison must use the owner's supported dispatcher and native executor seams,
with normal policy and capability checks. Any needed launch adapter must remain
at that execution-owner boundary. No provider command or retry coordinator is
added to TORC core.

Use the qualified narrow scorer for candidate execution. The general verifier's
root-read allowance is not evidence of blinded scoring. Preserve terminal owner
receipts, frozen packet hashes, protected source checks and scorer runtime hashes.
Use a dependency-only scorer environment: an editable TORC installation can
silently supply an absent baseline module and invalidate a negative control.

Before the first comparative admission, freeze exact task/context/scorer hashes,
runtime and policy, seed prompts, seeded trial order, and these limits. Retain
every start, failure, intervention and score; unresolved measurements remain
unknown. A launch packet and successful offline tests alone are not live results.
